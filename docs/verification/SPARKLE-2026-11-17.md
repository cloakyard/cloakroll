# CloakRoll: Sparkle, About updates and privacy

Verified 17 November 2026. [Configuration and publishing](../UPDATES.md).

## Scope and configuration

Sparkle 2.10.1 is pinned as an app-only dependency. Update controls are in About,
below the app/version information; the app menu also has Check for Updates. Checks
and automatic downloads start off, system profiling is disabled, and both the feed
and update archive require Ed25519 signatures. The Privacy views use identical update
disclosure text, while keeping each app's processing/storage details accurate.

Default Debug and Release builds use ad-hoc signing without a Team ID or provisioning
profile. The host's library-validation exception permits Sparkle to load without a
team identity. Release retains hardened runtime and excludes the debugger entitlement.
Provisioned distribution remains a separate project overlay.

The production public key is embedded in the build. The private key was generated by
the official Sparkle tool and remains in this Mac's login Keychain; it was not printed,
exported or committed. Keychain access for the official signing tools was approved by
the user. See the update guide for encrypted backup and future publishing steps.

## Update verification

- Debug and Release builds passed on Apple silicon / macOS 27.2.1 with Xcode 27.
  Final Release packaging used build `20261117.2`.
- `codesign --verify --deep --strict` passed. Release signatures are ad-hoc with hardened
  runtime, no Team ID, no debugger entitlement and no App Group requirement.
- Official `generate_appcast` and `sign_update` prepared and verified the final ZIP and
  appcast with the production Keychain key. Archive size/signature, feed signature,
  bundle/feed identity and increasing build numbers are checked by the packaging script.
  Duplicate, decreasing and malformed version inputs were rejected in local checks.
  A feed-generation check retained an older signed entry while adding the newer build.
- Disposable copies with separate bundle IDs and a test-only Ed25519 key exercised a
  loopback feed: `99.0.1` (build 1) found `99.0.2` (build 2), downloaded, verified,
  installed and relaunched. A subsequent check reported version `99.0.2` up to date.
  This complete path passed for CloakDrop, CloakTools and CloakRoll.
- A modified signed feed was rejected in CloakRoll's UI; the installed build remained 2.
  A same-size, one-byte-corrupted archive failed official Ed25519 verification.
- CloakTools' automatic-check/download preferences persisted across relaunch; both were
  restored to off. Light/dark update controls were inspected in CloakDrop and CloakTools.
- Final Release UI copies retained the production public key and used local copies of
  the checked-in signed empty feeds. Manual checks succeeded in all three. About and
  Privacy were inspected with native accessibility and screenshots. Screenshots were
  inspected in the tool session, not retained as repository artifacts.
- Test apps and the loopback server were stopped. Installed user apps were not replaced;
  CloakTools' prior Open With settings selection was restored.

Local verification artifacts are under `apps/macos/build/SparkleVerify-20261117.2/`
and intentionally ignored. Test release tags and archives were not published.

## App and website checks

CloakRoll's host keeps no network entitlement. Sparkle's sandboxed Downloader service
handles update requests; the separate installer service handles replacement. USB,
photo-library, chosen-folder and bookmark permissions remain unchanged. The complete
install/relaunch test exercised this service configuration.

- Strict SwiftLint passed.
- Hosted tests: 246 passed in 46 suites, with physical discovery disabled.
- `check_release.py` passed for final Release build `20261117.2`, checking signature,
  exact reviewed entitlements, runtime, architecture, icons and privacy manifests.
- Site `verify`, Cloudflare `check:worker` dry run and Air portability checks passed.
- The built site's appcast is byte-for-byte identical to the signed public source.

Website changes are policy prose and static feed headers/XML. No website layout or full
viewport/theme matrix was changed or recertified. USB device/hardware acceptance and the
existing beta release gates remain separate.

## Limits and publication

This verifies local ad-hoc update installation, not clean-machine Gatekeeper acceptance,
Developer ID signing, notarization, minimum-OS coverage, provisioned extensions or a
long-duration update schedule. Hardware workflows and unrelated transfer/backup behavior
were not recertified by these checks.

The checked-in website feed is signed and empty. No feed deployment, GitHub release,
DNS change or public installer publication occurred. Existing pre-Sparkle installs need
one manual replacement; future updates require publishing the archive first, then the
signed feed. Initial-install trust and possible privacy-permission prompts still apply
to unnotarized/ad-hoc builds.

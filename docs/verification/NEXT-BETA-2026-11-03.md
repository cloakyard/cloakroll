# Next-beta software stages — 3 November 2026

Physical iPhone and external-drive testing is deferred until the final acceptance stage
at the user's request. No fixture, mock or local build closes those gates.

## Stage 1 — backup health

Added a per-iPhone/destination overview, separate historical completion and latest-attempt
integrity evidence, folder access checks, and a route to review missing USB-visible items.
The existing saved-file checker now persists completed, nonempty checks. Stopped/failed/empty
checks never produce a new result. Recovery appending a committed original invalidates an
older check through a database trigger. New sessions have no invented integrity result.

Verification: 406 core tests, 227 hosted app tests, strict SwiftLint (153 files, zero violations),
and the normal arm64 Debug build pass. Migration fixtures were updated to recreate their
actual old schema before upgrading. New tests cover empty/partial histories, check persistence,
incomplete checks, stale results and phone/destination separation. Native UI inspection is
queued with the following software stages. Logs are in ignored `apps/macos/build/feature-health-*.log`.

An unrelated concurrent website edit appeared during this work and is excluded from native commits.

## Stage 2 — persistent continuation

New attempts persist their folder layout alongside the existing complete selected-resource
registration. Continue is available in Health and History for unfinished attempts. It matches
persistent phone identity, destination UUID, full unambiguous asset/component evidence and
keeps the original layout. All selected items must match; changed/unavailable/ambiguous items
block continuation instead of silently dropping part of the job. A transaction links each
continuation once. Historical outcomes remain unchanged, and the existing engine rechecks saved
originals and restarts unfinished components. Legacy attempts have no invented layout.

Verification: 410 core and 227 app tests, strict lint (155 files), and normal Debug build pass.
Four new core cases cover relaunch with new runtime IDs, partial companion evidence, wrong
phone/folder/layout, unavailable identities, legacy attempts and repeat continuation rejection.
Logs: ignored `apps/macos/build/feature-continuation-*.log`. Physical continuation and native
UI acceptance remain pending. Existing linkd.autoShortcut system diagnostics did not fail tests.

## Stage 3 — saved-original browser

Added Saved Originals with phone/folder selection, capture-date/type filtering, bounded
60-item keyset pages, companions, native Quick Look thumbnails/preview and Finder reveal.
Repeated sessions reuse one displayed resource entry. New backup registrations retain logical
media metadata; older records without it explicitly have unknown capture date/type. Folder
access is separate from recorded metadata. Original folder identity, no-symlink path walking,
regular-file type and size are checked before preview; this is not a checksum verification.
Four thumbnail requests may run at once, each owning a read-only lease through its callback.
Quick Look holds its own lease for the preview lifetime. No originals are modified.

Verification: 413 core and 227 app tests, strict lint (159 files) and normal Debug build pass.
Added pagination/filter/isolation, partial companion/repeat and unsafe/missing/wrong-root read
cases. Logs: ignored `apps/macos/build/feature-browser-*.log`. Native populated preview/access
lifetime inspection and physical removable-drive checks remain open. Public Quick Look APIs
were checked against Apple's documentation and the installed SDK.

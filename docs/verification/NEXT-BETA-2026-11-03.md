# Next-beta software stages — 3 November 2026

Physical iPhone and external-drive testing is deferred until the final acceptance stage
at the user's request. No fixture, mock or local build closes those gates.

## Stage 1 — backup health

Added a per-iPhone/destination overview, separate historical completion and latest-attempt
integrity evidence, folder access checks, and a route to review missing USB-visible items.
The existing saved-file checker now persists completed, nonempty checks. Stopped/failed/empty
checks never produce a new result. Recovery appending a committed original invalidates an
older check through a database trigger. New sessions have no invented integrity result.

Verification: 406 core tests, 227 hosted app tests, strict SwiftLint (153 files, zero violations),
and the normal arm64 Debug build pass. Migration fixtures were updated to recreate their
actual old schema before upgrading. New tests cover empty/partial histories, check persistence,
incomplete checks, stale results and phone/destination separation. Native UI inspection is
queued with the following software stages. Logs are in ignored `apps/macos/build/feature-health-*.log`.

An unrelated concurrent website edit appeared during this work and is excluded from native commits.

## Stage 2 — persistent continuation

New attempts persist their folder layout alongside the existing complete selected-resource
registration. Continue is available in Health and History for unfinished attempts. It matches
persistent phone identity, destination UUID, full unambiguous asset/component evidence and
keeps the original layout. All selected items must match; changed/unavailable/ambiguous items
block continuation instead of silently dropping part of the job. A transaction links each
continuation once. Historical outcomes remain unchanged, and the existing engine rechecks saved
originals and restarts unfinished components. Legacy attempts have no invented layout.

Verification: 410 core and 227 app tests, strict lint (155 files), and normal Debug build pass.
Four new core cases cover relaunch with new runtime IDs, partial companion evidence, wrong
phone/folder/layout, unavailable identities, legacy attempts and repeat continuation rejection.
Logs: ignored `apps/macos/build/feature-continuation-*.log`. Physical continuation and native
UI acceptance remain pending. Existing linkd.autoShortcut system diagnostics did not fail tests.

## Stage 3 — saved-original browser

Added Saved Originals with phone/folder selection, capture-date/type filtering, bounded
60-item keyset pages, companions, native Quick Look thumbnails/preview and Finder reveal.
Repeated sessions reuse one displayed resource entry. New backup registrations retain logical
media metadata; older records without it explicitly have unknown capture date/type. Folder
access is separate from recorded metadata. Original folder identity, no-symlink path walking,
regular-file type and size are checked before preview; this is not a checksum verification.
Four thumbnail requests may run at once, each owning a read-only lease through its callback.
Quick Look holds its own lease for the preview lifetime. No originals are modified.

Verification: 413 core and 227 app tests, strict lint (159 files) and normal Debug build pass.
Added pagination/filter/isolation, partial companion/repeat and unsafe/missing/wrong-root read
cases. Logs: ignored `apps/macos/build/feature-browser-*.log`. Native populated preview/access
lifetime inspection and physical removable-drive checks remain open. Public Quick Look APIs
were checked against Apple's documentation and the installed SDK.

## Stage 4 — storage preview

Normal selection/context/retry actions now review a captured selection and folder before
starting. Continuation opens the same review. The estimate freshly hashes reuse candidates,
counts missing components and companion bytes, shows free space or Unknown, and blocks a known
shortfall or unknown original size. Source/session/folder and selected asset values are checked
again at Start; the transfer engine retains its own verification and per-file space safeguards.
The estimate is advisory and does not reserve storage.

Verification: 416 core and 228 app tests, strict lint (161 files) and normal Debug build pass.
New cases cover exact capacity boundaries, deleted saved originals, partial companion reuse,
unknown capacity/size, overflow, no transfer during review, and changed source/folder rejection.
Logs: ignored `apps/macos/build/feature-preview-*.log`. Native review UI and physical full-drive
acceptance remain pending.

## Stage 5 — optional local notifications

Added a native Notifications settings tab with completion/attention notices and an optional
7/14/30-day, one-time reminder. Both are off by default. Authorization is requested only on opt-in,
and permission denial/revocation does not prevent disabling a preference. The reminder uses the
latest completed backup across phones, is replaced after success and is removed when disabled.
User-stopped backups stay quiet. Serialized scheduling and fixed identifiers avoid duplicate
pending reminders; generic content contains no phone, filename, path or failure-detail text.

Verification: four new injected-client cases cover defaults, authorization, denial/revocation,
private failure content, disabling, historical due dates and replacement after success.
The final hosted run passes 232 tests in 42 suites. Native Preview Settings showed both features
off, then accepted completion on and 7 days, and returned to off. Its notification client is
simulated: no OS permission prompt or actual delivery was tested.

## Integrated native UI evidence

Used the Debug **New Features · Generated Backups** window with three bundled illustrations,
an isolated temporary SQLite database/folder and a simulated source. No physical iPhone was
connected. The app's regular no-device screen was observed; no personal originals were imported.

- Health initially showed the previous one-item completion separately from the latest incomplete
  two-of-three attempt. Check Saved Files returned two of two matching and a dated result;
  the attempt remained incomplete.
- Continue matched three of three original selections. The storage review showed three originals,
  two freshly checked reuse candidates and about 55 KB additional space. Nothing transferred
  until Start. The new attempt completed all three, with no inherited integrity-check claim.
- A separate read-only SQLite/file inspection found transferred-byte totals of 50,161 for the
  initial job, 43,847 for the failed job and 54,657 for its linked continuation. The failed job
  retained its outcome. Independent Python size/SHA-256 checks matched all three unique saved files.
- Saved Originals showed all three dated items and generated thumbnails after continuation.
  Expanding an item and choosing Preview opened the native Quick Look image; Escape dismissed it.
  Type and capture-date filters produced the expected empty view.
- Health and Saved Originals were inspected at 1,100-point and 860-point widths in light/dark
  appearance. Long destination text wrapped. Compact date controls now occupy their own row,
  and the browser keeps its filters anchored when results become empty.
- Fixed an observed folder-picker timing issue by awaiting both history matching and projection
  before opening storage review. The health missing-items action now directly requests a fresh
  history check after navigation. Browser read failures distinguish database errors from folder
  access failures. Debug-only fixture labeling is kept outside the content layout.

These are generated local software checks, not USB or removable-drive acceptance. The native
accessibility tree exposed labels and selectable rows, but this tool did not establish full
keyboard traversal or VoiceOver spoken feedback. Sustained preview cancellation and physical
access-lifetime stress remain on the acceptance checklist.
